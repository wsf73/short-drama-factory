# 剧本评审与修复规程（评审官 / 修复器双角色）

> **定位**：本文件是"剧本医生"环节的**作业规范**。原 `dialogue-doctor-anti-ai.md` 只治台词 AI 味，属于**局部外科**；本文件补的是**完整的评审—修复闭环**——怎么诊断、怎么定级、意见该不该采纳、改到什么程度算完、什么时候必须停手。
>
> **触发**：用户要求"评审/看看这稿行不行""帮我改稿""剧本医生""这集差点意思""复核一下"；或流水线跑到 Step 4 精修、Step 8 合规复核时，**必读**。
>
> **来源**：整合自 JYY v3.8 `jyy-script-review` / `jyy-script-repair` 的证据化问题卡与修复纪律，映射到红果档位与付费墙口径。

---

## §一 两个角色，不要混着干

| 角色 | 只做什么 | 绝不做什么 |
|---|---|---|
| **评审官**（`/评审`） | 判断这稿是否兑现了约定的观看体验，给出**可核对的问题**与修订目标 | **不代替作者改稿**（除非用户明确要改） |
| **修复器**（`/修稿`） | 在**授权范围内做最小足够改动**，交付可直接替换的完整稿 | 不擅自扩大范围、不重写未授权部分、不"顺手美化" |

流程原则：**先评后修。** 一稿写完先跑评审；评审给出的问题卡再交给修复器。跳过评审直接改稿，最容易改成"没有具体毛病、但也没有味道"的平稿。

> 诊断和修改**分开输出**。评审报告里不要夹带改好的正文；修复交付里不要夹带长篇自评。

---

## §二 三种评审强度

| 模式 | 用于 | 读多少 | 输出 |
|---|---|---|---|
| `快审`（默认） | 刚写完的初稿 | 只读用户指定范围 | 3～5 条最影响观看的问题 ＋ **必须保留的长板**；**不填整套表格** |
| `专项` | 复核某一项（对白/断章/连续性/付费墙落位） | 受影响的相邻段 ＋ 必要前置事实 | 该专项结论；其他维度标**未测** |
| `终审` | 交付验收、整档交稿前 | 通读约定交付范围，分批核对 | 完整维度状态 ＋ 阅读覆盖 ＋ 主要跨单元未闭事项 |

**读不完就说读不完**：超出实际可读量时明确"已读 X 集、未读 Y 集"，交付部分结论，**不宣称完整通过**。专项通过**不等于**全稿通过。

## §三 问题卡（十一条字段）

每条重要问题都用这套字段；可以合并成自然语言，但**不许省略证据与影响**：

```text
id                  / 问题编号（同一根因合并成一条，不重复计数）
scope               / 范围（第几集、第几场、第几回合）
severity_by_impact  / 按影响定级 P0/P1/P2
evidence            / 证据：稿版本 ＋ 集场 ＋ 逐字短原文
observation         / 观察到什么（只描述文本里有的）
interpretation      / 为什么可能损害目标
target              / 想改善的观众体验（不是"改成什么样"）
protected_effects   / 必须保住的现有强项（改完后不许丢的）
allowed_edit        / 允许的改动范围（给足够小的建议范围）
downstream_checks   / 连带要复查什么（同期台词、后续集、台账）
status              / 待处理 / 已解决 / 已否决 / 待核
```

铁律：
- **`evidence` 必须逐字核对原文**，不许凭印象引述；
- 找不到支撑就标 **`待核`**，**不凑问题数量**；
- 对可能成立的替代解释做**最小核查**，别急着判罪；
- `target` 写"要改善什么体验"，**不写"把第 3 句改成……"**——修法是候选，不是命令。

## §四 严重度：按影响，不按类别

| 级别 | 判据 | 红果场景的典型 |
|---|---|---|
| **P0 阻断** | 核心观看承诺或明确交付要求失败 | 胜负无法理解；终局靠无来源信息成立；全篇对白持续难懂；约定的核心情绪始终没发生；付费墙处没有可断的钩子 |
| **P1 重大** | 重要段落或反复问题显著削弱体验，但不使核心交付整体失效 | 一整集的攻防原地打转；主角结果所有权不足；单元闭环只加钩子不给兑现 |
| **P2 局部** | 影响局部流畅或表现力，可在有限范围修正 | 单场信息复述；称谓不统一；某句台词不符身份 |

**关键**：
- **单一关键错误也可以是 P0**；次数多**不自动**等于 P0；
- 对白、喜剧、余味若本身就是本项目的核心产品（比如温情向项目的"暖"），**也可以阻断交付**；
- **任何关键失败不能被其他长板抵消**，"未测"不能冒充"通过"；
- 不要输出 **S/A 等级、总分、爆款预测**。

## §五 意见先核验，再决定采不采纳

修复器接到问题卡后，**第一件事是核对它在当前版本是否成立**，而不是照着改。以下情形尤其要复核：

- 意见来自**旧版本**（已被后续修改覆盖）；
- **没有引出短原文**；
- 意见把"直说 / 沉默 / 有依据的次优选择"一律判差；
- 意见**没声明适用条件**（例如默认"必须 9:16""必须付费墙在第十集""必须是女主型"）；
- 意见的**事实前提已被正文满足**——此时不得继续当作缺陷，只能否决，或改写成带明确条件的可选加强方案。

处置结果必须四选一：**采纳 / 部分采纳 / 否决 / 待核**，并简述重要分歧的依据。

> **审稿人的审美偏好不是命令。** 直白/留白、强爽/温情、严肃/喜剧，按项目目标裁决，不按谁声音大裁决。

## §六 结论分三层，别混着报

| 层级 | 内容 | 本 skill 的边界 |
|---|---|---|
| **文本质量** | 理解、人物、对白、情绪、过程、余味、连续性 | 本 skill 全责 |
| **平台适配** | 档位体量、场景数、黄金前 3 秒、断章落位、付费墙区间、合规红线 | 本 skill 全责（机检兜底） |
| **制作适配** | 画幅比例、分镜、资产、字幕字体、AI 生成可行性 | **超出本 skill 范围**，明确标注"未覆盖"，不要凭剧本正文给"可拍性""合规性""商业成功"认证 |

每个维度标 **达标 / 风险 / 失败 / 未测**，并写明适用性；非约定目标不强加验收。

**常见误判纠正**：
- 对白少 **不自动**等于视觉化；动作多 **不自动**等于有戏；
- 安静成立 与 空泛平淡 **分开判断**，不用"对白没错"代替整段有效，也不一律补争吵；
- 体量不因超出目标自动判质量差，也不因数字吻合放过删戏、注水、机械拆集。

## §七 修复纪律与回退判定

1. **先读受改段落、必要前置与后续依赖**，确定要改善的观看效果与必须保留的强项；缺失的后续标未核验，**不补造事实**。
2. **选足够的修复层级**：表达 → 场景 → 单集 → 核心关系/故事驱动 → 单元重构。
   - 局部补丁解决不了定位或关系失效 → **回到上游层整段重生**，不要继续堆补丁；
   - 但也不要一上来就重构——**能微调则微调**。
3. **优先替换，确实缺失才补**：先查重复说明、重复证明同一种情绪、无关程序；按完整段落做删除／合并试验，损失理解、人物、类型体验或必要余波时恢复或换实现。
4. **改完必须复查**：目标问题 ＋ 受影响连续性 ＋ **保护效果**。新问题若来自本次改动，改回。
5. **跨集扫尾**：修了某一句，要扫**同一集内所有同类问题**，不只改被点名的那一句。

### 回退判定（改坏了的表现）

出现以下任一项，视为**修复回退**，必须回滚或换实现：

- 逻辑更顺了，但**人物更平了**；
- 笑点、压迫感、亲密感、缺陷或余味**消失**了；
- 情绪被**提前解决**了（后面没有可走的空间）；
- 把风格化的完整句"口语化"成了统一碎句；
- 为了过机检而**注水**或**删掉必要过程**。

### 停手条件

同一问题**连续两次修改未见改善** → 换实现方式、缩小本次单位，或回到上游构思。**不无限循环自检，也不假称通过**；确实解决不了的，如实记录状态交付。

## §八 交付格式

**评审交付**：先给当前范围的结论与最大影响，再列**保留效果**、按优先级排列的问题卡、下一步。

**修复交付**：
- 简短改动报告（实际解决的问题 / 拒绝或未解决的意见 / 保护项 / 核验边界）；
- 约定范围的**完整替换稿**——正文里**不许**出现"其余不变""后续同理""略"；
- 标明 **原版 → 新版**、修改集场；拆合或重排场次时给**旧场 → 新场映射**，保持未受影响部分的编号与称谓；
- 长稿分批交付时，清单区分**已完成**与**待写**范围，不能把批次成果称作整剧完成。

**铁律**：正文脱离报告仍能成立；报告不能替代正文。
