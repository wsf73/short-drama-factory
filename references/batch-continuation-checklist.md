# 批量连写 · 收尾台账同步清单（Batch-Continuation Closeout Checklist）

> 适用：`/连写 N-M` 一批写完（≥5 集）之后的**强制收尾动作**。
> 为什么需要它：剧本正文过了 `validate_episode` 只是**单集**过关；`validate_series` 查的是**跨集台账**，
> 而台账不会自己跟着正文走。实测最常见的翻车不是正文写坏，而是**忘了同步台账**——
> 于是机检报一堆 S1/S4 WARN，被迫回头补。本清单把这 7 步固定下来，收尾一次过。

---

## 一、 七步同步清单（按序做，别跳）

### 1. 台账头部：`当前集: N`
台账第一段（`当前集: __ / 总集数: __ / 档位 / 流派 / 情绪契约 / 单元划分`）里的 `当前集` 是 **S1 的时间基准**。
**不同步这一行，S1 就不会触发**——它不会报错，只会静默地"看不见超期"。这是最隐蔽的一条：
你以为机检过了，其实是因为机检以为你还在第 13 集。

### 2. 伏笔账：状态 + 拟收 + 改期
逐条核对本批正文，凡**已回收**的，状态改成 **`收`** 开头（S1 只认"状态以 `收` 开头 = 已收"）。
> **陷阱 · S1 只在一个窗口里报**：`cur > 拟收 + 3` 才报超期。所以拟收集已过、但状态还写"养/未收"的，
> 一旦 `当前集` 推过 `拟收+3`，立刻炸 S1。两条出路：**①标 `收`**（真回收了）；**②改期**（把拟收改到真正要用的那集）。
> 改期是合法手段——本剧 FB-10（量房录像）就从原拟收 EP18 改到 EP62，因为 EP18 用的是另一段录音，两者不是同一条证据。
>
> **顺便做一次诚实性检查**：正文里"用掉"的物证，和伏笔账登记的是**同一个东西**吗？
> 别把"李芳自己录的那段"记成"FB-10 量房录像"——挂错 ID 会让后面几集重复回收。

### 3. 人物账：名册补齐（S4 唯一要求）
**本批任何有台词的新角色，必须进人物账第一列。** 不登记就报 `S4 第N集台词角色「X」不在人物账名册`。
- 工具人也算（锁匠、柜员、窗口工作人员、修手机师傅……）。
- 登记名**用正文里的原样称呼**。S4 用"包含"匹配（`nm in x or x in nm`），所以名册写"窗口工作人员"能覆盖正文同名角色；
  但名册写"柜员"覆盖不了"银行柜员"以外的变体——**用原样称呼最保险**。
- 老角色有新变化（关系现值/变动集）也要更新，否则热台账区会和正文脱节。
- **单集配额（E24 · 第一硬性规则）**：**每集都要卡「场景数 + 人物数 ≤ 4」，全系统优先级最高、优先于时长**——
  本批无论是否接生成管线一律卡。名册每多一个条目 = 多一张参考图。**同类工具位要并成一人**（中介甲+中介乙 → 中介），
  并表时**把台账两行并成一行**（否则 S7 四表与正文名册对不上）；
  被降为画外/动作/群像的角色若曾登记首出集，**首出集要后移到真正入名册那集**。
  **4 配额与本集时长冲突时一律保配额：缩短时长、拆集，或标【配额裁定】：配额优先，本集时长调整为 X 秒（降档交付，E16/E17 让位）。**
  规格 `references/reference-image-quota.md`。

### 4. 道具账：新增 + 状态机 + **回查一致性**
新增本批所有物证；已销毁/易主的更新状态。
> **陷阱 · 台账会正文打架**：旧台账写过"房产证第 17 集存入银行保险箱"，
> 但后续正文里她一直随身带着当众亮——两边冲突。**每批收尾都要回查一遍道具账与正文是否一致**，
> 尤其是"存入某处/交给某人"这类会限制后续可用性的状态。

### 5. 世界观规则账：补"引用集"
本批引用了哪条规则，就把集号补进"引用集"列；本批**新确立**的规则要新增一行（如"养老金账户可凭本人存折查询""柜台取现须本人签名"）。
规则账是后续集数**不写崩**的护栏——新规则不登记，后面就会写出"她凭什么能查到"。

### 6. 往返回合表 + 反转矩阵：对齐**实际**内容
- 往返回合表的"回合尾断章"要改成正文实际写的那句，别留着规划阶段的占位话术。
- 反转矩阵每一行的**标签顺序要和该三集的实际内容顺序对齐**。
  > 注意：`validate_series` 的 S8 **只读每行首个 `[A-I]` 标签**（`re.search(r"\[([A-I])\]", s)` 取第一个），
  > 所以行内标签顺序**不影响机检**——但会影响人读与后续对照。别偷懒。
- 本批若新增/调整了三集一块的标签，顺手跑一遍 S8：相邻 3 集（集号差 ≤2）内不得复用同一标签。

### 7. 热台账区滚动 + 冷归档区
- **热台账区**（"最近 5 集活跃状态"）：滚到本批最后 5 集，只留**未回收**伏笔；角色状态表更新到收盘状态。
- **冷归档区**：本批结案的伏笔、已下线角色、已销毁道具全部留痕，并**明确标注"待回归"**的角色
  （如"调解现场需到场"的调解员与当事人）——不标就会被下一批当成下线，写丢人。

## 二、 收尾后的两条命令（必须都跑）

```bash
# ① 一次看全体体量缺口（不必逐集试错）
python scripts/export_net_band.py <episodes 目录> --format standard

# ② 全剧台账机检（S1~S8）
python scripts/validate_series.py <台账文件> --episodes 80 --script-dir <episodes 目录>

# ③ 单集配额（第一硬性规则，每集必跑）：抓 E24，0 行 = 全体「场景+人物 ≤4」
for n in $(seq -w 1 80); do
  python scripts/validate_episode.py episodes/EP$n.md --format standard | grep "E24"
done
```

`export_net_band.py` 的存在就是为了消灭"差 3 个字"的来回：
E1 参考带是按**每集自报的【本集时长】**动态推导的，逐集跑 `validate_episode` 只能看到单集结论；
本脚本把 `净字数 / 参考带 / 缺口 / 对白占比 / 最长对白块` 一次全列出来，哪集差几字一眼看全。

## 三、 补体量的正确姿势（经验值，别踩坑）

| 做法 | 效果 | 副作用 |
|---|---|---|
| **补对白**（配角追问 + 主角短答，3~5 行） | 涨体量 **且** 涨对白占比 | 无（首选） |
| 补 △ 动作行 | 只涨体量 | 会**压低 E21 对白占比**，△ 行密集的集容易掉到 25% 以下 |
| 补独白/旁白 | 涨体量 | 受 E12 配额硬限（标准档各 1 处），且 E14 禁写抽象情绪 |

**加对白时同验 E19**：连续对白块 >95 字即 WARN。加完立刻跑，超了就在块中**插一条 △ 行**——
△ 行会**重置** E19 的累积，独白/旁白行也算断点。

**一次补够**：实测"差 1~50 字"时如果只补一两句，下一轮往往还是 WARN。
直接补 **40~80 字（3~5 行对白）**，留出余量，一轮过。

**每 4~5 行对白插一条 △**（实测踩坑）：E19 查的是**连续对白行的累计块**，不是单句。
一口气补 6~7 行对白（≈110~120 字）会直接把整块顶到 95 以上——本剧 EP49（119 字）、EP50（112 字）都是这么翻的。
**固定动作：补对白时每 4~5 行插一条 △ 行当断点**，既涨体量又守 E19。

**两个方向都要盯**：补 △ 行 = 涨体量 + **压** E21 对白占比；补对白 = 涨体量 + **抬** E21。
对白占比 60%+ 的集别再无脑加对白（上限 70%）；△ 行密集的集别再无脑加 △（下限 25%）。

**看 `export_net_band.py` 的「最长对白块」列就是 E19 预警**：>95 会直接标 `E19!`，不用单独跑 `validate_episode`。

**写之前先排对白行数，别写完再补**（本批最大教训）：标准档·对话型一集约需 **30~35 行对白**才够体量。
凭"够用就行"的感觉写，实测**必偏薄**——本剧 EP46~EP52 七集一次写完，**七集全部出带**（407~444，缺口 −100~−146）。
把对白行数当硬指标先排好，比写完再回头补省一半来回。

**"程序性场景"是最容易写薄的一类（第二次实测）**：调解室、法庭、办事窗口、医院走廊这类场景，
对白天然短而碎（"落。""坐下。""你签字。""下一个。"），△ 行又天然多 → 净字数看着够、其实全压在 △ 上，
E1 体量与 E21 对白占比两头都危险。本剧 EP71~EP75（调解室五集）首写**三集出带**（404 / 476 / 525），
EP76~EP79（客厅/食堂收尾四集）也**四集全出带**（464~533）。
**破解法**：让主角"**念出来**"——把清单、账目、条款、笔录一条一条念（每条约 12~22 字）。
一条念白 ≈ 三条碎对白，既撑体量又抬对白占比，还天然贴合程序性场景的真实语感。
本剧 EP72-73"逐条念三十年账"就是靠这个把两集一次写够（558 / 549）。

## 四、 语气词写法规整（下游导演端要机械分流）

神态短语里的语气词必须落在**四维词表**内，否则下游转译损耗：
嗓音质地（嘶哑/沙哑/气音/颤声/哭腔/哽咽/气若游丝/有气无力）、力度（低语/轻声/柔声/厉声/嘶吼/低吼/一字一顿/拖长音/压低声音）、
方式（冷笑/嗤笑/讥诮/阴阳怪气/咬牙切齿/咬着牙说）、节奏（急促/一字一顿/字字如刀）。

**三个高频坑，可机械替换**（机检 E18b 只在"全篇零语气词"时才报，所以不报不等于写对了）：

```
（小声）    → （压低声音）
（急）      → （急促）
（很轻）    → （低语）
（高声）    → （厉声）
```

批量替换时注意：`高声` 是 `提高声音` 的子串——**先替换 `（提高声音）`，再替换 `｜高声）` 与 `（高声）`**，否则会把"提高声音"改成"提厉声音"。

## 五、 三条容易踩的"结构类"坑（实测）

**1. 同一集可以有多条 `[场景]` 行。** 标准档 E3 上限 = 2，所以"内景·民政局办事大厅·日" + "内景·社区法律服务站楼梯间·日"
两行完全合法（本剧 EP47、EP52 都是两条 `[场景]` 行，PASSED）。
**S3 这类"功能族"场景**（所有出门办事/被围观的场都归它）本来就该拆成两条 `[场景]` 行——
别硬塞进一条，也别因为"换地点了"就以为超了上限。`_cap` 只在 `>195 秒` 的自定义长集才放宽（`round(时长/75)`）。

**2. 改反转矩阵行的标签顺序前，先确认 S8 会不会被影响。** S8 用 `re.search(r"(\d+)", 集数列)` 取**每行第一个数字**
（`EP43-45` → `43`），再比较集号差 `≤2` 的对。
- 若你的矩阵是"每 3 集一行"（1/4/7/10…），行首数字差恒为 3 → **S8 永不触发**，行内标签顺序可自由对齐实际内容。
- 若矩阵是"逐集一行"，则 S8 会真的按 3 集窗口比对，改顺序前必须复算。
改完跑一次 `validate_series` 即可确认。

**3. 反转矩阵的"标签顺序"要对齐**该三集的**实际内容顺序**，不是规划阶段的设计顺序。**别偷懒：**
设计顺序是写作时的轮换工具，矩阵是"实际写了什么"的记录。本剧 EP43-45 原设计 `[A][I][F]`，
实际内容顺序是"他摔的是复印件 → 当面提离婚 → 藏药盒"，对齐后写成 `[I][A][F]`。
（S8 不管行内顺序，所以这是**给人看的正确性**——别拿"机检能过"当借口不改。）

**4. 每集第一条 △ 必须塞一个冲突信号词（第二次实测，最大翻车点）。**
E4 取的是 `first_content_lines(text, 3)`——**跳过所有 `【】` 字段行和 `[场景]/[人物]` 行**，
直接看正文前 3 条（△ 或对白）。`△` 本身不算信号，得看行内文字。
本剧 EP67 / EP68 / EP73 / EP74 / EP75 / EP78 **六集**全栽在这里：开场写成
"客厅里坐满了人""老周把两把椅子摆开""旧八仙桌被抬到墙边"这类平和铺陈。
**固定动作**：每集第一条 △ 里塞一个 `CONFLICT_SIGNALS` 词——
`拍在 / 推 / 砸 / 按 / 签字 / 逼 / 骂 / 跪 / 撕 / 顶在 / 扔 / 吼 / 踹 / 拍`。
本剧后来统一改成"XX 把 YY **拍在** 桌上/墙上"就一次过。
> 注意：`拍着/拍开/拍了下` 都**不算**——机检是子串匹配 `拍在`，必须写足"拍在"两个字。

**5. 独白后面必须再跟一条 △ 或对白，别让独白成为断章前最后一条内容行。**
E13 查"独白/旁白紧贴断章收尾：断章必须落在画面/事件上"。
本剧 EP75 首写把内心独白放在倒数第二行、下一行直接是断章 → FAIL。
**固定动作**：写完独白，后面至少再补一条 △（画面落点），再写断章。

**6. `PASSED（含 WARN 请复核）` ≠ 过关。**
单集机检只在 E1 体量出带时报 WARN 而不拦，所以"PASSED"里可能夹着 E1 出带。
**固定动作**：每批收尾一律跑 `export_net_band.py` 看「缺口」列，缺口为负的集**必须补到正数**——
别只看 `validate_episode` 的 PASSED。本剧 EP77（−7）、EP79（−3）就是这么被 export 抓出来的；
若只看单集 PASSED 就会带着两集出带交付。

## 六、 全剧收官：合订交付（可选，但推荐）

散装 `EP01.md ~ EPnn.md` 交付给合作方/演员/导演端很难用，**全剧写完后跑一次合订**：

```bash
python scripts/merge_episodes.py <episodes 目录> \
    --title "《剧名》" \
    --header 04-合订本前言.md \
    --plan 02-分集规划-80集.md
```

产出两份（默认写到 `episodes` 的父目录）：

| 产物 | 内容 | 给谁 |
|---|---|---|
| `<剧名>全N集合订剧本.md` | 封面 + 结构速览 + 人物表 + 全剧目录 + 每集正文（**保留全部制作字段**） | 导演端转分镜提示词、AI 生成流水线 |
| `<剧名>纯正文版-N集.md` | 同上，但**剔除制作字段**，只留场景/人物/动作/对白/独白/断章 | 演员、合作方、需要通读剧本的人 |

**几个要点**：

1. **集数/集名/时长全部从正文里读**，不依赖规划文件——所以正文改了，重跑一次合订就是最新的，不会出现"规划说 110 秒、正文写 108 秒"的对不上。
2. **`--plan` 可给可不给**：给了就用分集规划表的"核心冲突"列生成总目录摘要，读起来一眼能扫；不给就只有集名。
3. **`--header` 传前言**：建议把"结构速览（三单元链/付费墙/四幕）+ 人物表 + 制作字段说明"做成一个 `04-合订本前言.md`。**别直接把立项卡丢进去**——立项卡首行是 `# 剧名·商业立项卡`，会跟合订本的 `# 剧名·全N集合订剧本` 撞成两个 H1，层级会乱。
4. **阅读版剔除的字段是白名单式**（`META_PREFIX` 里那 12 个 `【】` 字段），`[场景]`/`[人物]` 与 `【本集断章卡点】` **保留**——它们本身就是剧本的一部分。
5. **合订不替代机检**：先 `validate_episode` + `export_net_band` + `validate_series` 全绿，再合订。合订只是排版，不做校验。

> 实测（《六十岁，我不伺候了》80 集）：完整版 ≈ 13.2 万字符 / 阅读版 ≈ 10 万字符，一份 md 直接发得动。
> 若要 docx/pdf，走 `tencent-docx` 那条链路，别在合订脚本里加格式转换。
