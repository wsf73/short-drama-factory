# 模型选型：写剧本该用哪个大模型

> **核验日期：2026-10-02**。模型迭代极快，本文件的**清单**部分会过时——以 WorkBuddy 官方文档
> （设置 → 模型）为准；但**选型逻辑**部分（第一标准、分工、A/B 方法）是稳定的。
>
> 本文件回答的是"底座选谁"，不回答"怎么写"——怎么写由 SKILL.md 与其余 references 负责。

## 一、第一标准不是文笔

写短剧剧本与写小说是两种任务。本 skill 的产出要过 **E1~E24 二十四项机检**：
`[场景]` 少一行、断章缺落点词、体量出带、单集人物超 5 个——**任何一处格式错都直接 FAIL**。

所以模型选型的第一梯队标准是：

| 优先级 | 能力 | 为什么 |
|---|---|---|
| 1 | **指令遵循 / 格式稳定** | 不能自创排版、不能漏 `【】` 字段、不能把 `△` 动作写成散文 |
| 2 | **长程一致性** | 80 集连写，人物账 / 伏笔账 / 道具账不能崩（对应 S1~S8 台账机检） |
| 3 | **中文口语化** | 下沉剧要市井"人话"，不能书面腔、不能 AI 腔 |
| 4 | 文笔 | **最不需要靠模型的一项** |

> **关键判断**：文笔差，本 skill 的规则库能兜（六母型钩子库、五大断章公式、台词七维、
> 反 AI 腔词表、神态短语规格）；**格式跑偏，规则兜不住**。所以别拿"文笔测评"选模型。

## 三、推荐（按写剧本的适配度）

| 模型 | 适配度 | 依据 |
|---|---|---|
| **Kimi-K3** | ★★★★★ **首选** | 2.8T MoE、1M 上下文；公开实测中**长文本跨章节交叉验证最强、几乎不遗忘**——连写 80 集最不容易崩人物与伏笔 |
| **DeepSeek-V4-Pro** | ★★★★☆ **次选** | 中文语感稳、1M 上下文、**API 单价约为同级 1/5**——大批量连写成本最优 |
| GLM-5.3 | ★★★☆☆ | 强项是命令行 / Agent（Terminal-Bench 开源第一），**写作非其长项**；若看重"跑机检脚本 + 台账闭环"的利索度可选 |
| MiniMax-M3 · Kimi-K2.7-Code | ★★☆☆☆ | 定位代码 / 智能体，**不要用来写剧本** |

**省钱选 DeepSeek-V4-Pro，求稳选 Kimi-K3。**

## 四、想要更好的：自定义接入 + 分工

Claude 系在**中文自然度、人物一致性、伏笔回收**上目前仍是天花板
（2026-08 实测：10 个场景人物不走形、跨 8 章伏笔准确回收、AI 特征词出现率降 85%）。
它不在内置列表里，但可自定义接入。

**推荐分工**：

- **出初稿** → Kimi-K3 或 DeepSeek-V4-Pro（便宜、长程稳、能连写）
- **精修（`/剧本医生`）** → Claude 系（台词七维、断章打磨、去 AI 腔）
- 两者串起来：初稿便宜地铺量，精修贵一点但只花在刀刃上

## 五、比看一百篇测评都准的办法：用自己的稿子做 A/B

写完一部剧之后，你手上就有一份**现成的评测集**。挑三集覆盖三种最难的类型：

1. **对话型客厅戏**（嘴仗密集，考对白自然度与 E2/E19/E21）
2. **程序性场景**（调解室 / 办事窗口，天然最容易写薄，考 E1 体量）
3. **终局集**（考长程收束与情绪落点）

让候选模型各写一遍同一集，然后跑：

```bash
python scripts/validate_episode.py <该集> --format standard   # 谁一次过（0 FAIL）
python scripts/export_net_band.py <目录> --format standard     # 谁不出带（缺口为负）
```

**比两个指标：① 一次过率 ② 出带集数。** 这两个直接决定你要返工多少轮，
比任何"文笔评分"都实在。

## 六、通用大模型的边界（为什么必须有 skill）

短剧工具选型类文章的共识：**通用大模型（豆包 / DeepSeek 等）灵活度高、成本低，
但对短剧格式与行业规则理解浅，需大量人工调整**。

这正是本 skill 存在的意义——模型负责"按规则生成正文"，skill 负责
**格式契约（templates/episode-format.md）+ 质量兜底（E1~E24 机检）+ 跨集一致（S1~S8 台账机检）**。
**换模型不会脱胎换骨，模型只决定"一次过率"。**
